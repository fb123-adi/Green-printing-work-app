# Handoff: GPS Operations — mobile app (v1)

Green Printing Solution Pvt Ltd · Operations • Production • People · "One Platform. Complete Visibility."

## Overview
A single mobile app (Android-first, iPhone supported) used by every role at GPS. What a user sees depends on their role:
- **Employee** sees today's work, the next action, deadlines, proof upload, blocker reporting, submission for approval, and the end-of-day report.
- **Department Head** sees a team control room, an approvals queue, blocker resolution and task assignment for their departments.
- **Director (Super Admin)** sees the company-wide morning and evening control room, all jobs, approvals, announcements with acknowledgement tracking, the audit log and the Excel register.

The app creates accountability through verifiable workflow: assignments, system timestamps, evidence, approvals and audit trails. **No covert surveillance** of any kind (no microphone, camera, keylogging, screen recording or hidden location tracking).

## About the design files
The files in this bundle are **design references created in HTML**: working prototypes that show the intended look and behaviour. They are not production code. All data lives in the browser (localStorage), and all "security" in the prototype is simulated on the client.

**The task:** build this as a real application with a server, database and proper auth. Recommended stack if none exists yet:
- **Frontend:** React + TypeScript, shipped as an installable PWA (Add to Home Screen). Wrap it later with Capacitor for Google Play / App Store.
- **Backend:** Node (NestJS or Fastify) or Django, plus PostgreSQL. S3-compatible object storage for files.
- **Auth:** Argon2id password hashing, TOTP/SMS 2FA for privileged roles, httpOnly secure cookies, CSRF tokens, rate limiting.

## Authentication
- Login with Employee ID or email + password, "Remember this device" and "Forgot password" (the reset request goes to HR/Admin).
- The **Director account ID is `pradkum3639`**. In this public copy of the prototype the Director signs in with the demo password; no real password or password hash is stored in the code. **In production:** create this account through a server-side seed script with an Argon2id hash. The password must be set by the Director at first login and must never be committed to code. (The password was shared in a chat, so treat it as compromised and rotate it.)
- 2FA (6-digit code) is **required** for director and head accounts. 3 wrong codes send the user back to the login screen.
- 5 failed password attempts lock login for 60 seconds (rate-limit by account and by IP). Errors are generic ("ID or password is incorrect"), so it never reveals whether an ID exists.
- Idle session timeout: 15 minutes for the Director. Devices/sessions list with "Sign out other devices" (force logout).
- Every login, logout, export, approval and status change is written to the audit log.

### Employee IDs
- Generated by the server when an employee is created: `GPS-E###` for employees, `GPS-H###` for heads. Monotonic, never reused, never editable.
- New employee receives a one-time setup code by SMS or WhatsApp. They set their own password at first login.
- A leaver is **deactivated**, never deleted. Their history stays linked to their ID.

## Task state machine
`todo → ack → progress ⇄ blocked → submitted → approved | correction (→ progress) | rejected`

Each transition appends an **immutable TaskHistory row with a server timestamp**. Employees can never edit timestamps. When admins correct data, both the original and corrected values are kept in the audit log.

"Overdue" means `due < now` and status is not approved, rejected or submitted.
